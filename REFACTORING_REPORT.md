# Отчёт о рефакторинге

Полный рефакторинг репозитория по эвристикам Clean Code (AGENTS.md, разделы S0, C0–C5, E1–E2, F1–F4, G1–G36, J1–J3, N1–N7, T1–T9, разделы 8–12). Работа разбита на атомарные коммиты; после каждого этапа выполнялась полная верификация: сборка, все тесты, `dotnet format --verify-no-changes`. Итог: 108 тестов проходят детерминированно, 0 предупреждений компилятора, покрытие строк 98,42% (порог CI — 90%).

Документ объясняет каждое изменение по пунктам. Сокращённая сводка и актуальные ограничения — в `REFACTORING_BRIEF.md`.

## Подготовительные исправления (до рефакторинга)

### 1. Удалён дубликат тестового файла (коллизия регистров путей)

В индексе git одновременно лежали `Game.Tests/IoC/RegisterIoCDependencySendCommandTests.cs` и `Game.Tests/Ioc/RegisterIoCDependencySendCommandTests.cs` — два пути, различающиеся только регистром папки, с идентичным содержимым. На файловых системах Windows (регистронезависимых) второй файл физически не выгружался из репозитория, а git считал дерево чистым. Оставлен канонический путь `Game.Tests/IoC/`.

### 2. Починен CI-шаг сборки

Workflow `.github/workflows/ci.yml` устанавливал .NET SDK 8.0.x, тогда как оба проекта таргетируют `net10.0` — SDK 8 не умеет собирать net10.0 (ошибка NETSDK1045), поэтому шаг «Build Project» падал на GitHub с момента добавления генератора адаптеров. Версия поднята до `10.0.x`. Дополнительно добавлен `global.json` (SDK 10.0.300, `rollForward: latestFeature`) — сборка локально и в CI теперь использует одну и ту же линейку SDK.

## Коммиты рефакторинга

### 3. Гигиена контрактов сообщений и тестов команд

- Файл `Game/IMassageReciever.cs` переименован в `Game/IMessageReceiver.cs`: имя файла содержало двойную опечатку, а объявленный в нём интерфейс называется `IMessageReceiver`. Имя файла приведено в соответствие с типом.
- Текст исключения `SendCommand` заменён с `"recipient is busy"` на `"Message receiver is busy"` — предыдущий текст не назывался термином домена (класс называется message receiver) и был написан в разговорном стиле. Тест обновлён синхронно.
- Папки тестов `Game.Tests/commandTests/` и `Game.Tests/commands/` слиты в одну `commands` — обе содержали тесты команд, деление не несло смысла.
- Удалён дублирующий тест `Inject_ThrowsException_WhenCommandIsNull` (в классе уже был `Inject_Throws_When_Command_Is_Null` с тем же утверждением).
- Устранены предупреждения nullable (CS8625): в тестах null-контрактов явное намерение выражено оператором `null!` в точке вызова вместо переменной, объявленной как nullable.

### 4. Единая структура проекта и пространств имён

- Команды перенесены в `Game/Commands/` с namespace `Game.Commands` (раньше часть файлов лежала в `Game/commands/` с глобальным namespace, часть — с `Game`).
- IoC-регистрации получили namespace `Game.IoC`, доменные типы и интерфейсы — `Game` (раньше `IRotatable`, `ICommandInjectable`, `IMessageReceiver`, `Angle` жили в глобальном namespace).
- Имена файлов приведены к именам типов: `RotateCommands.cs` → `RotateCommand.cs`, `Actions.StartIoC.cs` → `RegisterIoCDependencyActionsStart.cs`, `Actions.StopIoC.cs` → `RegisterIoCDependencyActionsStop.cs`, `CommandInjectableCommandIoC.cs` → `RegisterDependencyCommandInjectableCommand.cs`, `MacroCommandStrategy.cs` → `CreateMacroCommandStrategy.cs`. Имя класса в файле уже совпадало — приведены только файлы.
- Повторяющийся код инициализации IoC в конструкторах 11 тестовых классов (`InitCommand` + создание скоупа + установка текущего) вынесен в фикстуру `Game.Tests/IoCTestScope.cs`.
- Все тестовые классы получили единый namespace `Game.Tests` (раньше вперемешку: глобальный, `Game.Tests`, `Game.Tests.IoC`, `Game.Tests.Strategies`).
- Следствие смены namespace `MoveCommand` (Game → Game.Commands): ключи генератора адаптеров строятся из полного имени типа, поэтому `Commands.Game_MoveCommand` стал `Commands.Game_Commands_MoveCommand`. Это соответствует задокументированному в `adapter_generator_architecture.md` правилу именования; тесты метаданных и документация обновлены синхронно.

### 5. Детерминированный запуск тестов

Обнаружено: IoC-контейнер внешних DLL — глобальное статическое состояние, а xUnit по умолчанию запускает тестовые коллекции параллельно. Из-за этого прогоны были недетерминированными (часть тестов проходила только за счёт «протёкших» регистраций из соседних коллекций). Добавлен `Game.Tests/xunit.runner.json` с `parallelizeTestCollections: false` — коллекции выполняются последовательно. Тесты не отключены, а сделаны воспроизводимыми.

Вместе с этим удалён тест `Execute_Should_Create_Command_Even_Without_Registered_Adapter`: его предпосылка («команда создаётся без зарегистрированного адаптера») противоречит реализации стратегии — она обязана получить адаптер и приводит его к `IMovingObject`. Без регистрации тест падал бы `InvalidCastException`; он проходил только если из ранее выполненного теста через цепочку скоупов «протекала» чужая регистрация, то есть кодифицировал гонку.

### 6. Иммутабельные value-типы Vector и Angle

- `Angle`: мутабельное статическое поле `denominator` (разделяемое изменяемое состояние — любым экземпляром можно было повлиять на все) заменено константой `FullCircleEighths = 8`. Свойство `Numerator` стало get-only (создание нового значения вместо мутации), `Cos`/`Sin` выведены через единственную функцию `ToRadians` вместо неявного приведения внутри себя, класс sealed, реализован `IEquatable<Angle>`.
- `Vector`: координаты копируются в конструкторе (защитная копия — внешний массив больше не может изменить состояние вектора), хранение скрыто (публичное свойство `Coordinates` не использовалось никем и удалено), добавлены guard-проверки null в конструктор и оператор сложения, класс sealed, реализован `IEquatable<Vector>`. Семантика равенства и текст исключения о несовпадении длин сохранены — они зафиксированы тестами.
- Добавлены граничные тесты: пустые векторы, null-операнды, защитная копия массива, обёртка угла через полный круг (`7+7 → 6`, `8+3 → 3`), равенство и хеш по модулю полного круга.

### 7. Guard clauses и именованные ключи IoC

- Создан `Game/IocDependencyKeys.cs` — все строковые ключи IoC-зависимостей (`"Commands.Move"`, `"Adapters.IMovingObject"`, `"Actions.Start"`, `"Specs.Move"` и остальные) вынесены в именованные константы. Раньше одни и те же литералы повторялись в файлах регистраций и в `StartCommand` — опечатка в одном месте молча ломала связку. Внешние ключи DLL (`IoC.Register` и т.п.) в константы включены, переименовывать их запрещено.
- Создан `Game/IoC/StrategyArguments.cs` — общий guard-хелпер `Get<T>(arguments, index)`: проверяет null массива и наличие индекса. Раньше каждая стратегия напрямую писала `args[0]` без проверки — при отсутствии аргумента наружу уходил `IndexOutOfRangeException` без объяснения. Теперь выбрасывается `ArgumentException` с сообщением, какой индекс и сколько аргументов пришло. Тесты обновлены синхронно (поведение «падение при отсутствии аргументов» сохранено, изменён только тип исключения на осмысленный).
- `StartCommand`: удалён двойной каст `((ICommand)Ioc.Resolve<ICommandInjectable>(...)).Inject(...)` — объект резолвится один раз как `ICommandInjectable`, приведение к `ICommand` выполняется явно в единственном месте, где он нужен; поле `_cmdType` переименовано в `_commandType` (без сокращений); ключ `"repeatable{тип}"` строится из константы `RepeatableCommandPrefix` — раньше тот же префикс дублировался строкой в `Actions.Stop`.
- `CreateMacroCommandStrategy`: поле `spec` переименовано в `commandSpecification`, стало readonly, добавлен guard на null в конструкторе, убран избыточный каст `(object)commands`.
- Все классы команд, регистраций и репозитория объявлены `sealed` — иерархий наследования в проекте нет, открытие классов для наследования ничем не обосновано.

### 8. Модернизация генератора адаптеров

- `AdapterSourceBuilder` переписан из процедурного накопления строк в `StringBuilder` (foreach, промежуточные мутации) в декларативный LINQ-конвейер: набор строк `usings` → заголовок класса → свойства → методы, склеенный `string.Join`. Логика свёртки членов интерфейса (дедупликация по имени/сигнатуре через `GroupBy`) сохранена.
- Форма генерируемого кода обновлена: раньше это был класс с мутабельным полем `_item` и конструктором, теперь — `sealed`-класс с primary constructor (`public sealed class Game_IMovingObjectAdapter(IDictionary<string, object> item) : Game.IMovingObject`). Сгенерированный код больше не содержит изменяемого состояния. Тесты, фиксирующие текст генерата, обновлены синхронно; интеграционные тесты подтверждают, что сгенерированный код компилируется и работает.
- `RoslynAdapterCompiler`: `HashSet` фильтра рантайм-сборок заменён на `FrozenSet` (только чтение), сообщения об ошибках компиляции переведены на английский в едином со всем проектом стиле.
- `IoCDependencyRegistrar`: удалён избыточный каст результата `Expression.Convert` к `Expression`, сообщение об ошибке «не ровно один конструктор» переведено на английский.
- `AdapterGenerator`, `CommandScanner`, `CommandMetadata` — sealed, поля оркестратора получили говорящие имена (`_scanner` → `_commandScanner`), хранимый список сборок приведён к `IReadOnlyList<Assembly>`.
- `adapter_generator_architecture.md` синхронизирован с новой формой генерируемого кода и новыми значениями ключей.

### 9. Тесты на ранее непокрытый код

- `RegisterIoCDependencyGameObjectRepository` (0% покрытия в baseline): два теста — зависимость регистрируется и резолвится как `GameObjectRepository`; повторные резолвы возвращают один и тот же экземпляр (контракт синглтона репозитория).
- `RoslynAdapterCompiler`: тест фиксирует контракт ошибки на невалидном исходнике (`InvalidOperationException` с диагностикой компиляции).

## Изменения поведения (важно для команды)

| Что | Было | Стало |
|-----|------|-------|
| Резолв команды без аргументов | `IndexOutOfRangeException` | `ArgumentException` с пояснением, какого аргумента не хватает |
| Текст ошибки занятого получателя | `recipient is busy` | `Message receiver is busy` |
| Сгенерированные адаптеры | класс с полем `_item` | sealed-класс с primary constructor; код адаптеров только генерируется, вручную не пишется |
| Ключи генератора | `Commands.Game_MoveCommand` | `Commands.Game_Commands_MoveCommand` (следствие namespace `Game.Commands`) |
| Порядок тестов | параллельные коллекции, недетерминированно | последовательные коллекции (`xunit.runner.json`) |
| Исключённые из API члены | `Vector.Coordinates` (публичное свойство) | удалено — не использовалось; доступ только через операторы и `Equals` |

Контракты внешних DLL (`App.Ioc`, `App.Scopes`, `InitCommand`, ключи `IoC.Register`, `IoC.Scope.Create`, `IoC.Scope.Current.Set`) не изменялись.

## Известные ограничения

1. `Common/core.dll` и `Common/scopes.dll` — внешние сборки курса, их API и поведение (включая накопление регистраций по цепочке скоупов) — фиксированный контракт.
2. Конструктор `MacroCommand` должен принимать именно `ICommand[]`: параметр-интерфейс вида `IReadOnlyList<ICommand>` попадает под критерии `CommandScanner` и ломает генерацию адаптеров (сканер ищет команды с единственным интерфейсным параметром конструктора).
3. Тесты должны быть самодостаточными: регистрации в скоупах накапливаются между тестами одного класса, рассчитывать на чужие регистрации нельзя.
