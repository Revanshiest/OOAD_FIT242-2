# Изменения серверной архитектуры

За основу взята ветка `feature/serverarch` на коммите `20053630bb76401036764439f2780b7486099dcc`. При исправлениях использованы сценарии из [аудита исходной версии](https://github.com/Revanshiest/OOAD_FIT242-2/blob/79af3e3a8688629f50c1fc3e1d70dbcb83fec69c/audit/serverarch-review.md). Отчёт аудита описывает более ранний код и не является отчётом о текущем состоянии ветки.

## Изменения

- Внешний Endpoint отклоняет внутренние команды с префиксом `Server.`. Динамические внутренние обработчики должны регистрироваться с тем же префиксом.
- Неуспешная аутентификация больше не расходует лимит сообщений игры. Некорректный timestamp не вызывает переполнение при проверке подписи.
- Подпись HMAC привязана к `messageId`. При переполнении очереди ответ содержит идентификатор выбранного потока; отсутствие активных потоков возвращает отдельный отказ.
- Маршрутизатор сохраняет идентификаторы потоков при удалении и повторном добавлении workers. Первичное назначение маршрута выполняется атомарно.
- Выполнение кванта прекращается, когда игра переходит в ожидание; ранний Resume учитывается для ожидающего в очереди Suspend. Завершённая watchdog игра удаляется из реестра получателей, а устаревший объект игры с повторно использованным ID не исполняется.
- При отклонении запроса миграции таблица маршрутов не переключается. Целевой поток разрешается до удаления игры у источника.
- Резервный поток повторяет неблокирующие попытки доставки и может завершиться при заполненной целевой очереди.
- Добавлены регрессионные тесты на изменения и на проблемные сценарии аудита.

## Совместимость HMAC

Формат несовместим с прежним: клиентам, самостоятельно вычисляющим подпись, необходимо включить `messageId` в подписываемую строку. Канонические данные: `key|gameId|command|commandArguments|messageId|timestamp`, где отсутствующий `messageId` представлен пустой строкой, а timestamp задан в секундах Unix. `commandArguments` должен совпадать с JSON-текстом, извлечённым серверным парсером, включая порядок полей и пробелы. Токен имеет вид `timestamp.lowercase_hex(HMAC-SHA256(secret, UTF8(канонические данные)))`.

## Оставшиеся ограничения

- Полный протокол бесшовной миграции не реализован: маршрут всё ещё может переключиться до восстановления игры на целевом потоке. Необходимы буферизация и упорядочивание сообщений, подтверждение установки снимка и безопасный откат при отказе.
- Остановка резервного потока прерывает повтор доставки; оставшиеся сообщения не сохраняются долговременно. Нужна согласованная политика завершения и перегрузки.
- Снимки не гарантируют восстановление произвольных команд и состояния уже ожидающей игры. Перезапуск не восстанавливает worker и игры из снимков.
- Принудительная остановка не гарантирует ограниченное время завершения для зависшей пользовательской команды. Межсерверная миграция и полноценное consistent hashing остаются незавершёнными.
- Нагрузочные тесты считают десериализацию сообщений; они не подтверждают успешное выполнение каждой игровой команды.

## Проверка

Запуск набора: `dotnet test Game.sln`. Набор регрессионных тестов не заменяет нагрузочные испытания и проверку миграции при конкурентном потоке запросов.
